# FOOTBALL DRAFT · 足球分队系统

录入球员 → 拖拽分队 → 记录单场数据 → 查看统计与排行榜。
**纯前端单页应用：不需要服务器、不需要数据库、不需要构建**，把文件夹丢到任何静态托管上就能用。

界面是足球主题：夜间球场背景、记分牌 HUD、每支球队都是一块带中圈和草坪条纹的小球场，球员是带号码和球衣配色的名牌。

## 四个功能区

| 区 | 能做什么 |
|---|---|
| **⚽ 比赛分队** | 从球员库勾选报名、拖拽分队、自定义队名队色、录比赛信息与比分、随机分队 |
| **👥 球员库** | 长期主数据：增删改、批量导入、去重、停用、合并重复球员、一键勾选报名 |
| **📋 比赛档案** | 每场比赛的比分与逐人数据（到场/进球/助攻/零封/MVP/SVP），可回看可改 |
| **🏆 统计排行** | 季度 / 年度 / 历史 + 内战 / 外战过滤，3 项概览 + 9 个榜单，CSV 导出；**搜索球员可查看单人完整数据卡与各项名次** |

### 需求对应

1. **球员库，比赛从球员库添加报名球员** —— 「球员库」里勾选 → 「加入本场报名」；也可在分队页点「从球员库添加」。新名字会自动入库。
2. **单场球员数据** —— 比赛档案展开逐人数据：进球、助攻、到场、门将零封、MVP、SVP。**进球/助攻帽子戏法由 ≥3 自动推导**，不提供手动开关（避免矛盾数据）。
3. **次数统计** —— 统计页三张概览卡：球队组织总次数、球员参加次数、胜场次数，均按「全部 / 内战 / 外战」拆分显示。
4. **排行榜** —— 出勤率、出场胜率、进球数、助攻数、进球帽子戏法、助攻帽子戏法、MVP、SVP、门将零封，共 9 个榜单，可按季度 / 年度 / 历史与内外战过滤。
   统计页顶部有**球员搜索框**：输入姓名或球衣号，所有榜单只显示匹配的球员；当唯一定位到一人时，上方会展开**球员数据卡**，一次列出该球员在当前口径下的 9 项数值、各项榜单名次，以及「参加 / 有效 / 胜 / 出勤率 / 胜率」明细。导出 CSV 也会遵循搜索过滤。

## 关键口径

详细规格见 [docs/SPEC.md](docs/SPEC.md)。要点：

- **MVP** = 胜队（内战）/ 本方（外战）最佳，全场 1 个
- **SVP** = **输队最佳球员**，全场 1 个；无明确输队（平局、外战取胜/平）则不评
- **内战**记各队比分自动判胜，并列最高为平局；**外战**记本方各队进球之和与对手进球
- **胜率分母** = 有明确赛果的参加场次；未录结果的比赛仍计入出勤率与参加次数
- **出勤率** = 到场场次 ÷ 筛选范围内全部已创建比赛
- **不设出场门槛**，全员参与排名；同分按参加场次多者优先；每行固定显示「参加 / 有效 / 胜」三列
- **只存原始事实**，所有统计实时聚合，绝不存计数器 —— 改动任何一场历史数据，全部榜单立即自洽

## 数据存在哪里

**只存在你自己的浏览器里**（`localStorage`，键名 `football-draft:state:v3`），不上传任何服务器。

- 换浏览器、换设备、清理浏览器数据都会看不到原来的数据 → **重要数据请定期用右上角「⤓ 备份」下载整库备份**
- 备份支持**覆盖导入**与**合并导入**（按姓名合并球员、按比赛 ID 去重）
- 页面有存储用量条，接近 5 MB 时会提示导出归档
- 无痕模式下 localStorage 可能不可用，页面会提示「存不下」
- 分享链接把单场比赛数据编码在 `#` 后面的片段里，**不会发给服务器**；对方打开是只读预览，点「复制到我的名单」即可接着编辑

## 从旧版本升级

从 v2（单场分队版）打开时会自动迁移：球员提升进球员库、旧单场包装成第一场比赛，原数据会原样另存一份到
`football-draft:state:v2-backup`。名单、分组、队名队色、比赛信息零丢失。
旧数据没有比分，统计会为空，需要补录。

## 部署到 GitHub Pages

```bash
cd 分队系统
git init
git add .
git commit -m "feat: football draft static site"
git branch -M main
git remote add origin https://github.com/<你的用户名>/football-draft.git
git push -u origin main
```

然后仓库 **Settings → Pages** → Source 选 `Deploy from a branch` → 分支 `main`、目录 `/ (root)` → Save。
一两分钟后访问 `https://<你的用户名>.github.io/football-draft/`。

也可以用 **Cloudflare Pages**（Workers & Pages → Create → Pages → Upload assets，把 `index.html`、`assets/`、`docs/` 拖进去）
或 **Netlify Drop**（<https://app.netlify.com/drop>，拖文件夹，不用注册先拿临时网址）。

> 项目全部使用英文文件名，GitHub Pages 不会遇到中文路径问题。仓库里的 `.nojekyll` 会阻止 Jekyll 处理下划线目录。

## 目录结构

```
index.html          页面结构（记分牌 / 四区导航 / 各类对话框）
assets/style.css    全部样式与响应式布局
assets/app.js       v3 数据模型、拖拽、统计聚合、备份/导入、分享
docs/SPEC.md        v3 规格说明书（口径冻结稿 + 黄金数据集验收基线）
robots.txt
legacy-flask/       最早的 Flask 版本（含服务端持久化），已不再需要，留作参考
```

## 说明

- `legacy-flask/` 是纯 Python 源码、无密钥，Pages 只托管静态文件、不会执行它
- 内置的 `window.__FD__` 只暴露只读查询与统计函数，供自动化验收脚本核对数字，不提供写入接口
