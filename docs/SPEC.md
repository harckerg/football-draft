## 1. 范围与非目标

### 1.1 范围内

| # | 需求 | 交付形态 |
|---|---|---|
| 1 | 球员库，比赛从球员库添加报名球员 | 独立主数据区 + 勾选报名 |
| 2 | 单场球员数据：进球、助攻、帽子戏法、MVP、SVP、门将零封 | 比赛档案详情录入 |
| 3 | 统计比赛次数（内战/外战分别）：组织总次数、球员参加次数、胜场次数 | 统计概览卡 |
| 4 | 排行榜（季度/年度/历史）：9 个指标 | 排行榜区 |

### 1.2 明确的非目标

- **不做后端、不做多设备同步、不做多人协作**。数据只存在组织者一台设备的浏览器里，
  GitHub Pages 静态托管不变。**用户已确认接受「清缓存 / 换设备即丢失」这一代价**，
  因此「整库备份 / 导入」是一等公民功能，不是附属功能。
- **不改变分享能力边界**：URL hash 能承载**一场比赛**，承载不了整个数据库。
  分享仍是单场只读预览；全库排行榜对外走「导出 CSV」或「独立 HTML 快照」。
- 不做账号、不做权限、不做实时协作、不做图片上传（头像等）。
- 不做多语言、不做主题切换，沿用现有足球皮肤。

### 1.3 已冻结的口径（用户确认）

| 项 | 冻结值 |
|---|---|
| 架构 | 纯前端 localStorage，组织者一人维护 |
| MVP | **全场 1 个**：胜队最佳（内战）/ 本方最佳（外战） |
| SVP | **全场 1 个**：**输队最佳球员**；无明确输队则不评 |
| 内战胜负 | 记各队比分 → 自动判胜；并列最高 = 平局 |
| 胜率分母 | **有明确赛果的参加场次** |
| 出勤率分母 | 筛选范围内**全部已创建比赛** |
| 榜单门槛 | **不设**，全部参与排名 |
| 同分排序 | 参加场次多者优先（仅影响同分次序，不影响上榜资格） |
| 帽子戏法 | `进球≥3` / `助攻≥3` **自动推导**，不存布尔值 |
| 门将零封 | 单场手动勾选 |
| 派生数据 | **只存原始事实，绝不存计数器**；所有统计实时聚合 |

## 2. 数据模型 v3

存储键：`football-draft:state:v3`（迁移时另存 `...:v2-backup` 保留原样）。

```js
{
  version: 3,

  // ---------- 球员库（主数据，跨比赛长期存在）----------
  roster: {
    "pl1": {
      id:        "pl1",
      name:      "张伟",           // 必填，1–24 字，库内唯一（大小写不敏感）
      number:    "10",            // 球衣号，可空，字符串
      position:  "GK|DF|MF|FW|",  // 位置，可空（仅作展示，不参与判定）
      joinedAt:  "2026-01-01",    // 入队日期，可空，仅展示
      active:    true,            // false = 停用/归档，不再出现在报名候选里
      note:      ""               // 备注，≤100 字
    }
  },

  // ---------- 比赛档案（只存原始事实）----------
  matches: {
    "m1": {
      id:     "m1",
      date:   "2026-05-20",       // 比赛日期，统计时段过滤的唯一依据
      type:   "internal",         // "internal" | "external"
      venue:       "工人体育场 3 号场",
      kickoff:     "2026-05-20T19:30",  // 沿用现有 datetime-local
      opponent:    "",            // 外战必填，内战留空
      note:        "",

      // 沿用现有分队快照（含自定义队名/队色）
      teams: [ { id: "t1", name: "闪电队", color: "#ff2d55", players: ["pl1","pl2"] } ],
      pool:  [ "pl3" ],           // 报名但未分队（替补席），仍算出勤

      // 比分（新增）
      scores:        { t1: 3, t2: 1 },  // 各队进球，键为 team.id
      opponentScore: null,              // 外战对手进球；内战忽略

      // 单场球员数据（新增）
      stats: {
        "pl1": {
          present:    true,   // 是否到场；入选时默认 true，可手动取消
          goals:      3,      // 进球
          assists:    1,      // 助攻
          mvp:        true,   // 全场唯一，见 §4
          svp:        false,  // 全场唯一，见 §4
          cleanSheet: false   // 门将零封，手动勾选
        }
      }
    }
  },

  currentMatchId: "m1",
  settings: { minAppearances: 0 },   // 保留字段，冻结为 0（不设门槛）
  updatedAt: "2026-05-20T12:00:00.000Z"
}
```

### 2.1 字段约束

| 字段 | 约束 |
|---|---|
| `roster[].name` | 库内唯一（trim 后大小写不敏感）；新增/改名时校验，重复则拒绝并提示合并 |
| `matches[].teams[].id` | 单场内唯一，正则 `^[A-Za-z0-9_-]{1,40}$` |
| `matches[].stats` 的键 | 必须是 `roster` 中存在的 id；也必须是该场 `teams[].players` 或 `pool` 中的 id |
| `goals` / `assists` / `scores` / `opponentScore` | 非负整数，上限 99；空值按 `null` 处理（不是 0） |
| `scores` 的键 | 必须是该场 `teams[].id`；外战时**本方所有球队进球之和**为 `ourGoals` |
| `mvp` / `svp` | 单场内最多各 1 个 `true`，录入界面强制互斥 |
| `present: false` 时 | `goals/assists/mvp/svp/cleanSheet` 一律清零并禁止录入 |
| `active: false` 的球员 | 不出现在报名候选，但**历史引用保持有效** |

### 2.2 不变式（P1 实现 `validateState()`，每次加载与保存前跑）

1. `currentMatchId` 必须存在于 `matches`（不存在则回落到最近一场或 `null`）
2. 每场 `stats` 的键 ⊆ 该场入选球员集合
3. 每场 `teams[].players` 与 `pool` 无交集，且都在 `roster` 中
4. 每场 `mvp`、`svp` 各至多 1 个
5. 球员合并后，B 的所有引用指向 A，B 置 `active:false` 且保留 id 供历史回查
6. **禁止物理删除有历史引用的球员**

## 3. 统计口径（精确定义）

### 3.1 术语

对一场比赛 `m` 与球员 `p`：

```
入选 inSquad(m, p)  = p ∈ (∪ m.teams[].players) ∪ m.pool
到场 present(m, p)  = inSquad(m,p) ∧ m.stats[p].present === true
                      （stats 缺省时按 present=true 处理）

已决 hasResult(m)   =
    internal: m.scores 中至少 2 个队有非负整数值
    external: ourGoals = Σ m.scores 有值 且 m.opponentScore 有值

胜队 winningTeams(m) =
    internal: 使 m.scores[t] 为唯一最大值的 {t}；并列最高 → 空集（平局）
    external: ourGoals > opponentScore → 全部本方球队；否则空集

获胜 isWin(m, p)    = hasResult(m) ∧ present(m,p) ∧ (p 所属队 ∈ winningTeams(m))
```

> **注**：逐人进球/助攻之和**不强制**等于球队比分（业余场景常漏记），
> 录入界面显示「队比分 3 / 逐人合计 2」提示差异，但不阻断保存。

### 3.2 统计范围

```
scope = { period, type } 的过滤结果，见 §5
M     = scope 内全部已创建比赛（含未录结果的比赛）
D(p)  = { m ∈ M : present(m,p) }              参加 / 出勤分子
V(p)  = { m ∈ M : present(m,p) ∧ hasResult(m) }  胜率分母
```

**未录结果的比赛**：仍计入 `M`（出勤率分母）与「组织总次数」，
但**不进** `V(p)`——即不把人算成「不胜」。这正是「胜率分母用有明确赛果的参加场次」。

### 3.3 概览统计（需求 3）

| 指标 | 公式 | 分口径 |
|---|---|---|
| 球队组织总次数 | `|M|` | 全部 / 内战 / 外战 三个数并排显示 |
| 球员参加次数 | 按球员列出 `|D(p)|`，可排序 | 同上 |
| 胜场次数 | 按球员列出 `|{m ∈ D(p) : isWin(m,p)}|` | 同上 |

### 3.4 九个排行榜指标（需求 4）

| # | 榜单 | 公式 | 空值显示 |
|---|---|---|---|
| 1 | 出勤率 | `|D(p)| / |M|`，`M` 为空时 0 | `0%` |
| 2 | 出场胜率 | `wins(p) / |V(p)|`，`V(p)=0` 时**不参与排名** | `—` |
| 3 | 进球数 | `Σ m.stats[p].goals` | `0` |
| 4 | 助攻数 | `Σ m.stats[p].assists` | `0` |
| 5 | 进球帽子戏法次数 | `|{m : goals ≥ 3}|` | `0` |
| 6 | 助攻帽子戏法次数 | `|{m : assists ≥ 3}|` | `0` |
| 7 | MVP 次数 | `|{m : mvp === true}|` | `0` |
| 8 | SVP 次数 | `|{m : svp === true}|` | `0` |
| 9 | 门将零封次数 | `|{m : cleanSheet === true}|` | `0` |

**通用规则**：

- 榜单**不设出场门槛**，所有 `roster` 中球员（含 `active:false`）全部参与排名；
  从未入选者以 0 值 / 0% / `—` 出现在榜尾。
- 同分时按 `|D(p)|`（参加场次）多者优先；仍相同按 `roster[].name` 字典序。
- 每行固定显示三列辅助信息：**参加 N / 有效 M / 胜 W**，便于自行判断小样本。
- 帽子戏法**自动推导**，不提供手动开关（杜绝「进 2 球却勾了帽子戏法」）。
- 所有统计**实时计算**，改任何一场历史数据，全部榜单立即自洽；不缓存、不落盘。

## 4. MVP / SVP 评选规则（SVP = 输队最佳）

**全场各 1 个**：`MVP` = 胜队/本方最佳，`SVP` = 输队最佳。数据层仍是
`stats[pid].mvp / .svp` 两个布尔，单场各至多一个 `true`。

| 场景 | MVP | SVP | 说明 |
|---|---|---|---|
| 内战，唯一最高分队 | 从该队选 1 人 | 从其余队（输队池）选 1 人 | 3 队以上时输队池为所有非最高分队 |
| 内战，并列最高（平局） | 不可自动评 | **不可评** | 界面提示「平局，无明确胜/负队」；允许手动标记 MVP 并给出警告色 |
| 外战，本方胜 | 本方 1 人 | **不可评** | 对手数据不记录，无可记录输队 |
| 外战，本方负 | 不可自动评 | 本方 1 人 | 本方即输队 |
| 外战，平局 | 不可自动评 | 不可评 | 无胜负 |
| `hasResult(m) === false` | 不可评 | 不可评 | 结果未录入 |

> **已知且接受的不对称**：外战赢球只产生 MVP、输球只产生 SVP，
> 因此 MVP 榜与 SVP 榜天然不对称，但语义自洽。

**界面约束**：录入区按「胜队 / 输队」两组展示候选，每组各限选 1 人；
选择另一组时自动清空冲突项。不可评场景直接隐藏或置灰对应分组。

## 5. 时段与类型过滤

| 过滤 | 取值 | 依据 |
|---|---|---|
| 时段 `period` | `history`（历史，默认）、`year:YYYY`、`quarter:YYYY-Qn` | `m.date` 的前 4 位 / 年月推算季度（Q1=1–3, Q2=4–6, Q3=7–9, Q4=10–12） |
| 类型 `type` | `all`（默认）、`internal`、`external` | `m.type` |

- 季度 / 年度下拉**只列出数据中实际出现过的取值**，按倒序排列。
- 两个过滤相乘生效；概览与九个榜单共用同一 `scope`。
- `date` 为空的比赛归入「未设日期」，在 `history` 下计入，在季度/年度下**排除**并在界面提示「N 场未设日期未纳入统计」。

## 6. v2 → v3 迁移

**触发**：加载时检测到 `version < 3` 或旧键 `football-draft:state:v1`。

1. 先把原始 JSON **原样**写入 `football-draft:state:v2-backup`（不修改、不覆盖已有备份）
2. `roster` 由旧 `players` 生成：`{ id, name, number:"", position:"", joinedAt:null, active:true, note:"" }`
3. 旧单场包装为 `m1`：
   - `date` = `match.kickoff` 的日期部分，无则取当天
   - `type` = `match.opponent` 非空 ? `external` : `internal`
   - `teams` / `pool` / `venue` / `kickoff` / `opponent` 原样搬入
   - `scores = {}`，`opponentScore = null`（旧数据无结果）
   - 每个旧球员生成 `stats[pid] = { present:true, goals:0, assists:0, mvp:false, svp:false, cleanSheet:false }`
4. `currentMatchId = "m1"`，`settings.minAppearances = 0`
5. 跑 `validateState()`，通过后写入新键；**任一步失败则保留旧数据、以只读模式打开并提示导出**

**兼容性目标**：老用户的名单、分组、队名队色、比赛信息**零丢失**；
统计因缺少历史结果而为空，属预期（需用户补录比分）。

## 7. 备份 / 导入格式

```js
{
  app: "football-draft",
  schema: 3,
  exportedAt: "2026-11-13T03:00:00.000Z",
  state: { /* 完整 v3 state */ }
}
```

| 模式 | 行为 |
|---|---|
| **覆盖导入** | 校验后整体替换，替换前自动留一份当前状态到 `...:pre-import-backup` |
| **合并导入** | `roster` 按 `name` 去重合并；`matches` 按 `id` 去重（冲突时保留较新 `updatedAt` 或询问）；id 冲突时重新编号并重映射引用 |

导入前后都跑 `validateState()`；失败则**不改动现有数据**并给出具体错误。
界面常驻显示存储用量条，超过 4 MB 提示导出并归档旧年份。
